# Доставлення посилок: консольний звіт

[![CI](https://github.com/dxom9kl/kzp-lab01-kost/actions/workflows/ci.yml/badge.svg)](https://github.com/dxom9kl/kzp-lab01-kost/actions/workflows/ci.yml)

Лабораторна робота № 1 з курсу «Кросплатформні засоби програмування», варіант 15.

Програма читає записи про доставлення посилок із CSV-файла, перевіряє кожен рядок,
обчислює чотири показники й записує однаковий звіт у консоль і текстовий файл.
Хибні рядки не зупиняють роботу: у звіті вказано номер рядка та причину пропуску.

## Формат входу

Файл у кодуванні UTF-8, один запис у рядку, поля розділено крапкою з комою,
рядка заголовка немає:

```text
id;weightKg;city;deliveryDays;express
```

| Поле | Тип | Правило |
|---|---|---|
| `id` | String | непорожній і унікальний у файлі |
| `weightKg` | double | число з крапкою (`2.50`), більше нуля |
| `city` | String | непорожнє, можна з українськими літерами, апострофом і дефісом |
| `deliveryDays` | int | ціле число, не менше нуля (`0` – доставлення в день відправлення) |
| `express` | boolean | лише `true` або `false` |

Порожні рядки, неправильна кількість полів, нечислові значення (`важка`, `2,50`, `NaN`,
`1e3`, пробіли навколо числа) і від'ємні числа відкидаються з поясненням.
Приклад даних – [`data/input.csv`](data/input.csv): 8 коректних і 21 хибний рядок.

## Показники

1. Кількість коректних записів.
2. Середня вага посилки, кг.
3. Найбільший термін доставлення разом з ідентифікатором і містом посилки.
4. Кількість експрес-доставлень.

## Збірка

Потрібен JDK 21. Maven установлювати не треба: Maven Wrapper сам завантажить версію,
указану в `.mvn/wrapper/maven-wrapper.properties`.

```text
mvnw.cmd clean verify        # Windows
./mvnw clean verify          # macOS, Ubuntu
```

`verify` компілює код, запускає тести, збирає виконуваний jar і перевіряє байт-код SpotBugs.

## Запуск

```text
java -jar target/lab01-1.0.0.jar
java -jar target/lab01-1.0.0.jar --input data/input.csv --output out/report.txt
java -jar target/lab01-1.0.0.jar --help
java -jar target/lab01-1.0.0.jar --version
```

| Аргумент | Призначення | За замовчуванням |
|---|---|---|
| `--input <файл>` | вхідний CSV-файл | `data/input.csv` |
| `--output <файл>` | файл звіту | `out/report.txt` |
| `--help` | довідка | |
| `--version` | версія з `pom.xml` і номер збірки | |

Коди завершення: `0` – успіх; `1` – файл не знайдено, не прочитано чи не записано або в
ньому немає жодного коректного запису; `2` – помилка в аргументах.

У консолі Windows перед запуском виконайте `chcp 65001`, інакше частина українських
літер може вивестися як `?`. Файл звіту завжди записується в UTF-8.

## Структура

```text
src/main/java/ua/lpnu/kzp/
├── Main.java                 точка входу: парсер аргументів → контролер → код завершення
├── DeliveryController.java   керує обробкою: файл → перевірка → показники → звіт
├── ExitCode.java             коди завершення
├── BuildInfo.java            версія з pom.xml і номер збірки
├── cli/                      Arguments, ArgumentsParser, UsageException
├── delivery/                 ParcelParser, InvalidRecordException, DeliverySummary
└── report/                   ReportFormatter, FileReport
```

## Версія

Версію продукту записано лише в `pom.xml`. Під час збірки Maven підставляє її у
`version.properties`, а `--version` додає номер збірки: `1.0.0+local` для локальної
збірки і `1.0.0+<N>` у CI, де `N` – номер запуску GitHub Actions. Стан лабораторної
роботи № 1 позначено Git-тегом `v1.0.0`.

## CI

[GitHub Actions](.github/workflows/ci.yml) на кожен Pull Request, push у `main` і тег `v*`
запускає `verify` на `ubuntu-latest`, `windows-latest` і `macos-latest`, перевіряє вивід
`--version`, запускає jar на `data/input.csv` і публікує jar як артефакт
`lab01-<ОС>-build-<N>`.
